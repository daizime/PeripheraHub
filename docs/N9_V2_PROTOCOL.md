# ATK N9 V2 ULTRA 只读适配

记录日期：2026-10-19。实现为独立 C++ 代码；没有复制或打包厂商 JavaScript，也没有套用旧 N9 串口协议。

## 来源与型号边界

- [ATK 官方产品页](https://www.atk.store/products/atk-neptune-n9-v2-esports-gaming-wireless-headset) 声明 N9 V2 支持桌面与网页 ATK HUB，支持板载 EQ；其虚拟 7.1 功能另要求桌面应用。此声明不能证明第三方程序已经实现音效算法。
- [ATK 官方网页驱动](https://hub.atk.pro/) 本次引用资源：`https://bpcdn.atkgear.com/hub-v3/production/3.2.28/static/demoMode.store-DQmSowxd.js`，SHA-256 `D7F81A1FAA5F52C401476144448CF4379C1E164E90C865E4CE694FCA20527B64`。
- 该资源设备表将 `373B:12D6` 对应到 N9 V2 ULTRA 接收器，`373B:12D5` 对应有线模式，控制器 model 为 `bolutek`；控制器的查询、状态解析及 PEQ 读取用于核对报文事实。
- 本机只实测了 `12D6`。有线 `12D5` 来自厂商设备表，仍需插线验收，不能写成已测支持。
- [旧 N9 开源实现](https://github.com/ibroxiim/atk-n9-mac) 的 Ultra 接收器 PID 为 `1204`，使用串口；不能把旧报文发到本机 V2 HID。

## 本机已核对的接口

同一接收器有 Consumer、Telephony、`FF90:0001` 和 `FF82:0001` 等集合。有效查询通道为 **Usage FF90:0001，输入/输出长度 64 字节，Report ID 0x55**。`FF82` 使用 Report ID 0x41，不能混用。

本机 FF90 的输出为常量报文字段，未出现在 HidP 输出 Value/Button caps 中；不能把 caps 中“无输出数据项”直接当作无控制通道。已在准确匹配接口后，用原生 WriteFile/ReadFile 完成 64 字节查询与响应。每次打开仍核对 VID/PID、Usage、长度及输入 Report ID，未知接口不发送命令。

## 查询格式与实测

下列偏移均包含首字节 Report ID；未列出的请求字节为零。未观察到应用层 CRC，不能自行添加。

| 请求 | 字节 |
|---|---|
| 设备信息/电量 | `[0]=55, [1]=65, [2]=01`（十六进制） |
| PEQ 单点读取 | `[0]=55, [1]=69, [2]=01, [3]=点序号 0..9` |

状态响应：`[1]=65`；`[2]` 为电量百分比；`[3]` 电池状态 2=放电、3=充电、4=充满；`[4]` EQ 模式代码；`[5..9]` 为设备报告的 7.1、空间音效、自动关机、耳返开关和耳返音量字段；`[10..13]` 接收器版本；`[14..17]` 耳机版本；`[18]` RGB 标志。协议字段存在不等于所有型号都具备相应可调硬件。

本次采样返回 **80%，状态 2，耳机版本 0.0.2.9，接收器版本 0.0.1.7**；这只是采样值，不是固定电量。

PEQ 响应：`[1]=69, [2]=01`；频率 `[3..4]`、有符号增益 `[5..6]`、Q `[7..8]` 使用大端；增益和 Q 分别按 1/10 dB、1/10 单位显示；`[9]` 类型、`[10]` 启用标志。实际读出 10 个点；第一点为 **64 Hz、−2.0 dB、Q 0.9、类型 1、启用标志 0**。银行代码 1 不擅自翻译成某个情景名称，也不据此宣称该曲线当前已生效。

PEQ 响应不回显点序号；查询必须串行，超时后关闭句柄并停止本轮，不能继续把迟到回包归到下一点。异步 I/O 取消完成后才释放缓冲区。不能在同一通道并行操作厂家软件与本程序来做参数验收。

## 模块与当前范围

- `src/core/n9_protocol.*`：纯 C++ 查询构造、严格响应解析和档案字段校验；另有开发探针使用的候选 PEQ/模式写入编码，产品界面不开放 N9 写入，不提供配对、恢复出厂或升级功能。
- `src/platform/WindowsN9.cpp`：原生接口核验及串行读取；与 VGN 共用 `internal/HidReportIO.h`。
- `DeviceService`：后台采样，常规 20 秒缓存；手动刷新强制重读；设备移除清除缓存。
- `RuntimeSnapshot::headsetForContainer`：只在非空 Container ID 唯一匹配时，将 HID 读数关联到音频端点，不按名字或通用序列号猜测。
- `HeadsetDetails`：共用界面主题，独立只读组件；显示电量与 PEQ 原始参数，不提供尚未验证的 EQ 调节开关。
- `ProfileTracker` / `DeviceProfiles`：保存实际读数；输出档案保留 PEQ 与状态字段，输入档案保留电量；负增益可原样落盘和重载。这些私有字段暂不自动写回耳机。

待完成：EQ 写入与实际听感/板载保留验证、充电状态变化、有线/无线身份与切换、耳机关闭时缓存和断开事件行为、其他私有功能，以及和厂家桌面音效的兼容性。以上未验收前仍为 Demo。

PEQ 写入帧（命令 `68`）与 EQ 模式写入（命令 `21`）的候选报文见 `PRIVATE_WRITE_CANDIDATES_2026-10-19.md`。注意写入帧比回包多一个点序号字节，两者偏移不能共用。当前只有编码器与单元测试，没有写入入口。
