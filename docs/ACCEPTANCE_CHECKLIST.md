日期：2026-10-19。这份清单把 `RELEASE_READINESS_2026-10-19.md` 里"仍缺少"的项拆成可以直接照着做的步骤。**每一项都要留下原始输出**，不要只记结论。

分层规则不变：报文身份、运行中写入、写后回读、物理效果、断电保存、发布验收是六个层级，不能用一层代替另一层。

## 0. 准备

1. 关闭厂商驱动（VGN 网页驱动、ATK HUB、LANGTU 软件），避免两边同时读写同一设备。
2. 鼠标测试期间**持续移动鼠标**，它只在运动时回包。
3. 探针在 `work\native-write\`，产品程序在 `work\build-vs\PeripheralHub.exe`，数据目录默认是程序同目录的 `data`。
4. 每做完一项，把命令和完整输出贴进对应记录文件，再继续下一项。

也可以直接用引导脚本，逐项提示、自动记录到 `work/verification/acceptance/`：

```powershell
.\scripts\acceptance-run.ps1          # 只打印计划，不动硬件
.\scripts\acceptance-run.ps1 -Run     # 逐项执行，每项前需回车确认，输入 q 跳过
```

脚本已在两种非破坏模式下验证过：计划模式输出计划并落盘记录；执行模式下逐项输入 `q` 能完整跳过并正常退出（未触发任何设备写入）。真正的执行步骤仍需你本人在场。

A1 不再假设"原值是 3200"：脚本先只读一次拿到第 4 档真实值，测试后按**那个值**恢复；读不到就不写入。这是 2026-10-19 那次 N9 事故（用切换前的读数判断切换后的写入）之后统一改掉的假设——写入类步骤必须先读当前状态，再决定恢复目标。

脚本文件必须保存为 UTF-8 **带 BOM**，否则 Windows PowerShell 按 ANSI 解码会让中文字符串语法错误。

## A. VGN F2 Master+（DPI / 回报率 / 当前档位）

已完成的证据：三条写入均"写入→回读→改回"通过。剩余三件事。

### A1 物理效果

```
.\work\native-write\vgn_dpi_write_probe.exe --stage 3 --x 1600 --y 1600 --apply
```

指针速度应当明显变慢。确认后改回：

```
.\work\native-write\vgn_dpi_write_probe.exe --stage 3 --x 3200 --y 3200 --apply
```

记录：**你本人是否感觉到速度变化**，以及变慢发生在哪一次操作之后。

### A2 断电保存

1. 保持第 4 档为 3200。
2. 关闭鼠标电源，等 10 秒，再打开。
3. 等鼠标响应后运行：

```
.\work\native-write\vgn_dpi_write_probe.exe --stage 3 --x 3200 --y 3200
```

记录：`CURRENT_STAGES` 里的 stage 3 是否仍是 3200；如果是别的值，说明写入没有真正落到非易失存储。

### A3 拔插与充电切换

1. 保持程序运行，拔下接收器 5 秒再插回，观察卡片是否恢复读数、是否出现重复设备。
2. 插上数据线充电（不改通信通道），观察电量是否显示在充电状态，DPI/回报率是否仍可读。
3. 如果插线后切换到有线通道，重新运行探针确认接口身份（应为 `FB57`），并记录此时能否读写。

记录：每一步之后的连接状态、读数来源、是否需要手动刷新。

### A4 并发安全

同时打开 VGN 网页驱动与本程序，运行一次只读探针。记录是否出现超时或"配置在读取期间改变"。

## C. KTC H24T7（只读复核 / 切源风险 / 双屏）

### C1 只读复核

启动 `PeripheralHub.exe`，展开显示器卡片"更多"，点"读取显示器功能"，记录亮度/对比度/输入源/情景/色彩四个枚举与当前值是否仍与 `MONITOR_CONTROLS.md` 的 2026-10-18 记录一致。

### C2 切源（有已知风险，需你明确同意）

已有记录：软件切源后持续花屏，需要切回 DP 才恢复。**在弄清原因前不建议再用软件切源**。若要继续排查，请先确认两件事：

- 显示器实体按键能在花屏时把输入源切回 DP（即不会失去唯一的恢复手段）；
- 你接受一次可能的花屏。

满足后运行一次切换并记录：切到哪个源、何时开始花屏、能否再切回、需要显示 OSD 还是软件即可恢复。

### C3 双屏

接入第二台显示器（任意型号均可），记录：是否两个显示器都能被识别、亮度是否分别可调、切换目标后能力串是否重新读取、旧目标的迟到结果是否被丢弃。

## E. 系统级

### E1 休眠唤醒

1. 启动程序，确认三张卡片都有读数。
2. 睡眠 → 唤醒。
3. 在 `data\peripheral-hub.log` 中查找两行：

```
System resume: forcing a full device refresh
Resume refresh completed in <N> ms usb <true/false> audio <...> monitor <...> errors <N>
```

记录：`N` 的值、三个子系统是否都成功、卡片是否在无需手动刷新的情况下恢复读数。

### E2 托盘与后台

最小化到托盘后拔插鼠标接收器，观察托盘摘要与卡片是否同步更新；这会验证隐藏窗口时设备通知仍然生效。
