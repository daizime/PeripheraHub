## VGN F2 Master+：EEPROM 写

厂商的函数先构造 16 字节负载，再由传输层在前面加 Report ID `08`，共 17 字节。这与已验证的读取帧一致（读取命令 `08`，校验为 17 字节求和低 8 位等于 `55`）。

写入命令为 `07`，帧布局：

| 偏移 | 含义 |
|---|---|
| `[0]` | Report ID `08` |
| `[1]` | 命令 `07` |
| `[2]` | 固定 `00` |
| `[3..4]` | 地址，大端 |
| `[5]` | 数据长度，1..10 |
| `[6..15]` | 数据，不足补 `00` |
| `[16]` | 校验 |

校验算法与读取相同：`[0..15]` 求和取低 8 位，`[16] = 55 - 和`，因此 17 字节整体求和低 8 位为 `55`。

### 已核对的地址

| 名称 | 地址 | 长度 | 记录格式 |
|---|---|---|---|
| 回报率 | `0` | 2 | 值 + `(55 - 值)` |
| 档位数量 | `2` | 2 | 同上 |
| 当前档位 | `4` | 2 | 同上 |
| DPI 档位 | `12 + 4×档位` | 4 | 见下 |

DPI 记录 4 字节：`[0]` X 低位、`[1]` Y 低位、`[2]` flags、`[3]` 记录校验。flags 的 `[1:0]`/`[5:4]` 是 X/Y 倍增位，`[3:2]`/`[7:6]` 是高 2 位值；`[3] = 55 - ([0]+[1]+[2])`。

这与 `decodeDpi` 已实现并实机验证过的解码完全互逆：`(低位 + 高位×256 + 1) × 50 × 2^置位数`。因此本机第六档 42000 既可以写成倍增位 `01`、值 419（厂商写法），也可以写成倍增位 `00`、值 839；两种都还原为 42000。

实现取「先试无倍增」的规范形式，并**拒绝**无精确表示的 DPI，不做就近取整。未改动档位一律保留原始 4 字节原样回写。

### 与厂商保存路径的差异（必须验证）

厂商保存配置时把 `0..255` 整幅镜像按 10 字节分块重写，`3955` 传感器另写 48 字节。本项目实现的是**只写改动的那一条 4 字节记录**。分块写本身是厂商协议的既有能力，但没有证据表明部分写入会被固件拒绝或需要额外的提交步骤。

因此实机验收必须覆盖：写 4 字节 → 回读该记录 → 物理效果（鼠标移动速度/DIP 灯档位）→ 断电保存后再读。若部分写不被接受，回退方案是照厂商路径重写受影响分块，而不是扩大到整幅镜像。

## ATK N9 V2 ULTRA：PEQ 与 EQ 模式

厂商驱动先构造 63 字节负载，再由传输层加 Report ID `55`，共 64 字节；无应用层校验，与已验证的读取一致。命令枚举中 `PeqSet = 104 (0x68)`、`PeqGet = 105 (0x69)`、`Eq = 33 (0x21)`。

单点 PEQ 写入：

| 偏移 | 含义 |
|---|---|
| `[0]` | Report ID `55` |
| `[1]` | 命令 `68` |
| `[2]` | 银行 `01`（本机唯一观测到的取值） |
| `[3]` | 点序号 0..9 |
| `[4..5]` | 频率，大端 |
| `[6..7]` | 增益，有符号 16 位大端，单位 0.1 dB |
| `[8..9]` | Q，单位 0.1 |
| `[10]` | 类型 0..5 |
| `[11]` | 启用标志 |
| `[12]` | 字段掩码，`1F` 表示全部字段 |

**注意偏移**：回包不含点序号，因此 `parsePeq` 读到的频率在 `[3..4]`，而写入帧的频率在 `[4..5]`。两者相差一字节，不能共用同一组偏移。

Q 在厂商侧被限制在 `5..50`（0.5..5.0）。本项目不夹取，超出范围直接拒绝。厂商发送该帧时**不等待回包**，所以写入确认只能靠随后的 `69` 单点读取。

EQ 模式写入：`[0]=55 [1]=21 [2]=01（写选择器） [3]=模式 0..2`。同一命令读取时 `[2]=00`，模式回显在 `[1]`。

### 实测约束：PEQ 点写入要求 Custom 模式

2026-10-19 实机：在 `eqMode = 0`（Game1）下发送单点写入帧，设备返回正常但**回读未改变**，即写入被静默忽略。厂商网页驱动的应用预设路径在写点之前先执行 `setEqMode(2)`（Custom），批量写入函数也在 `Custom` 分支内才逐点写。

因此写入顺序必须是：切 Custom → 逐点写 → 需要时切回原模式。模式切换本身会改变听感，测试必须在用户在场时进行，并在结束后恢复原模式。设备状态未因该次被忽略的写入而改变。

记录见 `work/verification/n9-peq-write-probe-20261019/README.md`。

## 实现与边界

- `src/core/vgn_config.*`：`encodeDpiRecord`、`encodeScalarRecord`、`encodePollingRate`、`flashWriteQuery`。只接受上表列出的地址与长度组合；其他地址、其他长度、非精确 DPI 一律返回空。
- `src/core/n9_protocol.*`：`peqWriteQuery`、`eqModeWriteQuery`。点数、频率、Q、类型越界一律返回空。
- VGN 三项白名单写入已接入 `DeviceService` 和默认关闭的实验性界面开关；N9 写入仅用于独立开发探针，产品界面未开放。候选帧编码不代表已经通过物理效果与发布验收。
- 明确不做：整幅 256 字节镜像写、按键/宏写、恢复出厂、固件升级、任意地址写。
