# 动态设备卡片与保存档案

## 当前设备与历史设备

控制区按鼠标、显示器、键盘、音频分组，每类一张卡片，同类多台设备通过下拉列表切换。扫描确认该类没有可管理接口时隐藏卡片，其他卡片紧凑排列；全部为空时显示空状态。展开详情仅切换卡片内部内容。枚举失败保留上次存在性并显示读取暂不可用，不作为拔除证据。

音频卡片分别提供输出与输入下拉菜单，各自对应音量、静音和独立选择记录。两个音量控制共用服务入口，内部使用独立的实时合并通道，避免调整麦克风时取消输出音量请求。下拉弹层与闭合控件共用 `UiTheme`，选中态、悬停、焦点和滚动条保持一致。所有下拉框通过 `createThemedComboBox()` 创建：闭合框可按布局收缩并省略长名称，提示保留全文；弹层按内容扩宽，超过当前屏幕宽度时可横向滚动。图标为预渲染 PNG，嵌入 Qt 资源，由 Qt Gui 加载，不需要 QtSvg 运行 DLL。

新设备名称来自 Windows 显示器信息、HID 产品信息或音频端点名称。系统没有提供具体型号时显示通用名称，不按相似名称猜型号。同一设备的多个 HID 集合按可靠 ContainerId 与类型分组；没有可靠身份时不凭名称或 VID/PID 无条件合并。系统枚举的内置、虚拟接口也可能出现在列表；接口存在与无线从机在线分开显示。

当前发现范围是上述四类。通用协议可以自动读取型号或设备名称及其开放能力；未知厂商的 DPI、按键、RGB、EQ 等私有功能需要型号适配，不能从型号名称自动推导报文。已核验的 VGN 专用电量查询保留；其他未知 HID 不发送配置报文。显示器功能见 `MONITOR_CONTROLS.md`。

## 保存什么、何时保存

“已保存设备”是独立侧栏页面，按鼠标、键盘、显示器、音频设备分类展开；音频再分输出、输入，未知历史方向单列待识别，其他类别归入其他设备。分类节点可展开和收起，设备叶子显示独立详情。定时刷新保留当前选择、分类展开状态和滚动位置，断开设备仍留在原分类下。

每条档案保留设备名称、分类、最后检测时间及已支持的实际参数：亮度、音量、静音、有效原生情景/输入源/色彩代码、对比度，以及可读取的最后电量和充电状态。未知字段缺失，不能用 0 或 false 代替。电量与充电是最后读数，不是可恢复的设置。音频输入/输出方向由 Windows 端点的 capture 属性记录，不能凭名称猜测；旧档案下次识别后补全方向。

已核验的 F2 Master+ 另保存启用 DPI 档位的 X/Y 值、活动档位、回报率、六个按键类型/参数及已解析的性能字段。N9 V2 输出档案另保存状态和已读 PEQ。以上私有字段均为实际读数，目前只保存，不自动写回；不是设备全部内部存储的备份。协议与范围见 `VGN_F2_PROTOCOL.md` / `N9_V2_PROTOCOL.md`。缓存配置的成功采样时间独立记录，失败/过期数据不会覆盖最后确认参数。

用户提交的目标先标为待确认；实际新读数到达后才更新确认状态。其他软件修改的实际音量、亮度也会进入记录。普通连续操作做 500ms 保存去抖，滑块松手、卡片连接集合变化、关闭窗口及退出时立即落盘；元数据每分钟检查保存。物理拔除后只能保存最后成功读到的值，不能在链路断开后补读未知参数。

档案位于数据目录 `devices.json`，使用版本化 JSON 和 QSaveFile 原子保存。原有 `settings.ini` 保留选择项和手工关联。档案按系统设备/端点身份区分，HID 非空序列号和 VID 参与身份摘要；不会仅因两台设备名称相同共享参数。音频的播放与麦克风端点分别保存。缺少硬件唯一序列号的设备仍受系统身份能力限制，更换端口可能产生新档案；同型号设备的物理身份不能凭型号保证。

文件大小限制 1 MiB、设备记录最多 512 项。损坏或不兼容的档案拒绝覆盖并提示错误；不会静默用空档案替换原文件。

## 单独删除设备档案

在“已保存设备”分类下选择具体设备，详情底部提供“删除设备档案”。先结束使用并断开设备连接，等待扫描确认“未接入”后才允许删除；2.4G 设备需要拔出对应接收器，仅关闭无线设备本体不等于接口已断开。该入口不负责禁用 Windows 设备或关闭显示器。

确认对话框固定目标设备 ID；确认后执行一次新的完整扫描，再核对对应类别是否成功枚举且目标仍未接入。设备在确认期间重新接入、相关枚举失败、恢复操作尚未结束或磁盘提交失败时保留档案并说明原因。只删除选中的设备记录，音频输入/输出档案分别处理；分类下最后一台删除后收起空分类。写盘失败会恢复内存记录，防止后续定时保存把失败的删除写回。

成功删除立即原子落盘，迟到的回读不会重建记录。下次实际重新接入时按首次发现处理，读取当前名称与已支持参数，不恢复已删除的目标值。删除不会重置设备自身设置，也不代表更换了硬件型号。

## 重连自动恢复

首次发现没有历史档案的设备只读取、保存当前状态。已有档案重连时，自动恢复先前实际确认过的亮度、音量、可用情景。每项使用当前精确接口 ID 重新验证；发送后做一次回读，不重试或自动回滚。

历史输入源可靠时，传递只读 `last_input` 匹配上下文：当前输入源相同才恢复旧显示设置；输入源不同则沿用当前所有显示设置；无法可靠确认时跳过依赖该来源的恢复。不会自动发送输入源命令。如果没有可靠历史输入源，独立亮度仍可恢复，情景必须另外通过当前枚举和读数校验。H24T7 本轮输入源与情景回报不一致，未确认的模式不会自动恢复。

静音、对比度、色彩、输入源和 HID 读数只记录，不自动写回；这样不会在接入时突然取消静音或切走当前画面。设置失败或只恢复部分参数时，保留记录和原因，不能显示成已全部恢复。每类别实际采样时间独立记录，避免音频读回把旧显示器缓存伪装成新数据。

私有参数（VGN 的 DPI、回报率、当前档位）**不参与自动恢复**：重连只读取并保存当前值。用户可在设置里开启"实验性设备写入"后手动写入，写入不属于恢复流程，也不在启动或重连时自动发生。

## 模块入口

| 模块 | 职责 |
|---|---|
| `core/hid_discovery.*` | 纯 C++ 键鼠用途分类、型号名称与接口分组 |
| `core/device_features.h` | 统一功能枚举、标准 VCP 双向映射 |
| `DeviceService::setFeature(id, feature, value)` | 控制区与详情共用的设置入口，校验后转交现有排队控制 |
| `widgets/DeviceCard.*`、`DeviceGrid.*` | 一致卡片外观、内部切换、显隐和排列，无设备 I/O |
| `widgets/UiTheme.*` | 下拉、数值与滑条统一创建；长名称、主题和滚轮防误触，动态子对话框继承同一规则 |
| `DeviceProfiles.*` | 参数记录、确认状态、格式校验和原子持久化；`remove(id)` 负责离线单档案删除及提交失败回滚 |
| `ProfileTracker.*` | 连接会话、采样时效、保存边界和自动恢复协调；`removalBlockReason(id)` / `removeProfile(id, error)` 统一核对删除条件与清理会话 |
| `SettingsRestore.*` | 纯 C++ 恢复白名单、来源匹配、重新验证和一次回读 |

```cpp
service.setFeature(monitorId, DeviceFeature::Brightness, 45);
service.setFeature(endpointId, DeviceFeature::Volume, 20);
```

目标 ID 来自枚举结果。亮度和音量保留原有合并队列；程序填充控件使用信号阻断，不因显示设备或打开“更多”就写入参数。新增型号优先扩展发现与协议适配，复用卡片、服务和档案模块，不添加平行的 UI 或存储逻辑。

音频选择分别使用 `selectVolumeTarget(outputId, false)` 与 `selectVolumeTarget(inputId, true)`，提交仍然统一调用 `setFeature(id, DeviceFeature::Volume, value)`，松手调用 `finishVolume(id)`。手动刷新通过 `requestRefresh()` 返回的票号匹配 `refreshFinished`；旧扫描或局部读回不能冒充新请求的完成，忙时会等待当前控制结束后执行完整强制扫描。连续请求采用最新票号，较旧票号不单独完成；主窗口统一协调，一次只保留一个待完成请求。
